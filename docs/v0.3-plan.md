# Pawnix v0.3 — Steering(计划 → 交付归档)

> **状态:已交付(有欠账)。** 本文原为 4 周实施计划,现改为交付记录 —— 保留原始计划正文作为历史,逐项加 ✅/⚠️ 标注实际落地情况。更新于 2026-08-28。
>
> 主题:**让 agent 从一次性问答的 chatbot,变成可以陪你跑一整天的搭子**。三个动词:**可打断 / 可围观 / 可托管**。
>
> 一句话结论:三大特性都能用;地基周基本完成;但 **Goal token 预算守护、专门 todo 工具、`/goal start` 语法**这几处"计划里写了、代码里没落地或落地方式不同"。完整欠账见 [§7](#7-交付欠账--与计划的偏差)。状态总览见 [STATUS.md](STATUS.md)。

## 1. 用户视角的三件事

| 体验 | 现状 | v0.3 之后 |
|------|------|-----------|
| **可打断** | agent 跑起来是黑盒,要么等完要么 Ctrl+C | turn 进行中能在 Web 输入框追加"补充指令",下一轮 tool call 前 agent 看到 |
| **可围观** | tool 结果一行行刷,看不出整体进度 | `/plan` 出方案 → 用户审 → 执行;per-session `todo.md` 进度面板 + 内联"继续/调整方案"按钮 |
| **可托管** | 提一个长期目标只能拆成 cron + 多次提问 | `/goal <objective>` 起一个长目标(⚠️ 实际无 `start` 子命令,直接跟目标),idle 时自动续跑;`/goal pause/resume/clear` 三件套已通;⚠️ token 预算守护未接线(见 §7) |

非目标(主动放弃,留给后续大版本):

- per-chatter MEMORY/USER 隔离 —— 单用户场景不需要
- workspace S3 后端 —— 单机够用
- 多 channel 多气泡 / GFM 表格扁平化 —— Discord 已够用
- 完整 plugin hook 系统 + 插件市场 —— 没有第三方插件作者
- PromptMode + ToolAllowlist UI —— 自己写 SOUL.md 比点 UI 快

## 3. 四周节奏

### Week 1: 地基(必须先做完) — ✅ 基本完成

> Origin 枚举、skills 按需加载 + token 预算、pgvector 读写路径均已落地;onboarding P0 已修(见 onboarding-issues.md)。注:任务 3 的读路径实际实现在 `BuildSystemPromptWithMemory`(`context.go`),而非计划里写的 `BuildSystemPromptSections`。

| # | 任务 | 来源 |
|---|------|------|
| 1 | `bus.InboundMessage.Origin` 扩展枚举值:`goal_context` / `subagent` / `user_steer` / `heartbeat`,加 const + 兼容性测试 | 借鉴 fastclaw `575721e` 思路 |
| 2 | skills 按需加载:`BuildSkillsSummary` 改为只输出 name+desc,新增 `load_skill` 工具按需读 body;加 skills section token budget | fastclaw `181165c` + 本地 `docs/system-prompt-improvements.md` P1 |
| 3 | Memory pgvector 读路径接通:`BuildSystemPromptSections` 加 semantic search 注入(限 1-2KB);AutoPersist 写入路径打开 embedding pipeline | 本地 `docs/memory-improvements.md` P0-1/P0-2 |
| 4 | onboarding 收尾:`handleLaunch` 加 waitForGateway 轮询;Telegram UI 字段补齐 | 本地 `docs/onboarding-issues.md` Bug-8/Bug-10 |

**验收**:新装用户从 onboarding 到第一次对话不再有"假装成功"的卡死;system prompt 在 28 个 skill 时控制在 ~1.5k token 以内;`memories` 表的 embedding 列不再全 NULL。

### Week 2: 可打断 (Mid-run Steering) — ✅ 已交付

> mid-run steering 已通(`loop.go` 每轮 ReAct 头部 `drainSteerIntoMessages`)。⚠️ 实际路由是 **`POST /api/chat/tasks/{id}/steer`**(不是计划里写的 `POST /api/chat/steer`)。

| # | 任务 |
|---|------|
| 1 | bus 加 `SteerHook`:agent loop 在每轮 tool call 之前 drain 一次 pending steer 队列,把消息追加到 messages |
| 2 | 新接口 `POST /api/chat/steer`,body 同 `/api/chat/submit` 但带 `taskID`;命中 turn 进行中的 task 时,把消息以 `Origin=user_steer` 投递到 bus 的 steer 队列 |
| 3 | Web UI:turn 进行中输入框不锁,placeholder 改成"补充指令(不会打断,会追加到下一步)";发送按钮文案变"追加",turn 结束自动恢复 |
| 4 | 前端轻量提示:agent 在下一轮看到 steer 时,emit 一个 `chat_event` `{type:"steer_received"}`,UI 渲染一个气泡提示"已并入下一步" |

**验收**:在一个跑了 5 轮 tool 的长任务中追加"换一只票看看",下一轮 tool call 之前 agent 已经 pivot。

### Week 3: 可围观 (Plan + todo.md 进度面板) — 🟡 部分

> `/plan` 出方案、Web `TodoPanel` 轮询 `todo.md` 已通。⚠️ 但**没有专门的 `todo_write`/`todo_check` 工具**(任务 2 未落地),agent 靠通用 `write_file` 维护 `todo.md`;`/plan` 也**不自己写** `todo.md`,只 nudge 模型下一步去写,且 nudge 文案里引用的 `update_todo` **是不存在的工具**。

| # | 任务 |
|---|------|
| 1 | `/plan` slash 命令:用户输入 `/plan <objective>` → agent 一次性产 plan(不动工具)→ 写入 session 的 `todo.md` |
| 2 | `todo_write` / `todo_check` 工具:agent 在执行中可以勾选已完成步骤 |
| 3 | Web 进度面板组件:在 chat 右侧固定一栏,渲染 `todo.md` checkbox 状态,实时更新 |
| 4 | plan 气泡内联按钮:`继续执行` / `调整方案`,后者把 plan 当 user 消息回灌让 agent 改 |

**验收**:用户开 `/plan 复盘今天恩捷股份的走势并给出明日操作建议` 后能在右侧看到 5 步 todo,执行过程实时勾选。

### Week 4: 可托管 (Goal MVP) — 🟡 部分

> goal 包 / `agent_goals` 表 / `/goal` 命令族 / PostTurn `TryFireContinuation` / `Origin=goal_context` 续跑均已通。⚠️ 但**任务 5(token accounting hook)未接线**:`FoldUsage`/`BudgetLimitPrompt` 无生产调用方,创建 goal 从不设预算,`status=budget_limited` 永不触发。防跑飞目前只靠 continuation 的 tight-loop 闸(`slash_goal.go`)。

| # | 任务 |
|---|------|
| 1 | port `internal/agent/goal/` 包(goal.go / store.go / continue.go / prompt.go / templates) |
| 2 | port `internal/store` 的 `agent_goals` 表迁移 + `GoalRecord` |
| 3 | port `internal/agent/slash_goal.go` 的 `/goal` 命令族 |
| 4 | 在 PostTurn hook 里调 `TryFireContinuation`,bus 的 `Origin=goal_context` 走通到 agent loop |
| 5 | token accounting hook(AfterModelCall)接进来,`status=budget_limited` 时发 budget_limit prompt |
| 6 | 在两个交易账户上 dogfood 一周 |

**Goal MVP scope 限制**(不在这版做):

- 不做 Web UI 的 goal 列表/编辑页(只走 slash)
- 不做 `/goal budget <N>` 中途调预算
- 不做跨 session 共享 goal
- 不做 SSE 事件流(等 v0.4)

**验收**:`/goal 盯着恩捷股份突破 85 提醒我,跌破成本线 5% 强提醒`(⚠️ 无 `start` 子命令,直接跟目标)能创建一条 active goal,后续每个 turn 自动注入 continuation,直到模型 call `update_goal` 标 complete 或用户 `/goal clear`。

## 5. 风险与回退

| 风险 | 回退方案 |
|------|----------|
| Goal continuation 死循环烧 token | token budget 是 MVP 必带项,不是可选;默认 budget = 50k token |
| mid-run steer 消息打乱 tool sequence | steer 只在"下一次 tool call 之前"注入,不打断进行中的 tool;实在需要硬停的用 Ctrl+C |
| pgvector embedding 写失败但 agent 表现正常("墓地"复发) | 写入路径加 metric;Heartbeat 30 分钟里巡检一次"近期 memory 行 embedding NULL 比例",超阈值告警 |
| port fastclaw 代码引入它独有的 per-chatter / workspace 抽象副作用 | port 时严格按 v0.3 scope,fastclaw 那边的 per-chatter 字段在 claw-os 这边继续走单 owner 路径 |

## 6. 验收 demo 清单(v0.3 发版前必跑)

1. **可打断**:开一个 deep-research turn,中途追加"重点看新能源板块",下一轮 tool call 前 pivot。
2. **可围观**:`/plan 复盘今天的两个账户` → 看到 5 步 todo → 实时勾选 → 中间点"调整方案"重排。
3. **可托管**:`/goal ...`(无 `start`)→ 4 个连续 turn 看到 continuation 注入 → `/goal pause` 静默 → `/goal resume` 续跑 → 模型调 `update_goal` 标 complete → 状态变 complete 不再续跑。
4. **地基**:onboarding 走一遍不卡;`SELECT count(*) FROM memories WHERE embedding IS NULL` 应该是 0(新写入);`SELECT length(prompt)` 装 28 skill 时 < 1500 tokens。

## 7. 交付欠账 / 与计划的偏差

回填于 2026-08-28,基于对代码的逐条核对。三大特性都能用,但以下几处"计划里写了、代码里没落地或落地方式不同",在这里集中记账,避免后人拿本计划当实现说明书。

| # | 计划承诺 | 实际 | 影响 | 落点 |
|---|----------|------|------|------|
| 1 | Goal token 预算守护是 MVP 必带项(默认 50k) | `goal.FoldUsage`(`goal/accounting.go`)/`goal.BudgetLimitPrompt`(`goal/prompt.go`)均无生产调用方,`Goal.TokenBudget` 恒为 nil(创建 goal 从不设预算),`status=budget_limited` 永不触发 | **长目标烧 token 的风险实际未被拦**;现只靠 continuation tight-loop 闸兜底 | `internal/agent/goal/accounting.go` · `internal/agent/hooks.go`(缺 AfterModelCall 接线) · `slash_goal.go` |
| 2 | `todo_write`/`todo_check` 专用工具 | 未实现;agent 靠通用 `write_file` 维护 `todo.md` | 进度面板依赖模型遵守文件格式约定,跑偏就断 | Week 3 任务 2 |
| 3 | `/plan` 写入 session 的 `todo.md` | `/plan` 只出方案 + nudge 模型自己去写,不自己落盘 | 需要模型配合;plan nudge 文案里引用的 `update_todo` 是**不存在的工具**(dangling ref) | `internal/agent/slash.go` |
| 4 | `POST /api/chat/steer` | 实际路由 `POST /api/chat/tasks/{id}/steer` | 文档/客户端按旧路径会 404 | `internal/setup` 路由表 |
| 5 | `/goal start <objective>` | 无 `start` 子命令,`/goal <objective>` 直接起 | 按 `start` 语法调用会被当成目标文本 | `slash_goal.go` |
| 6 | 读路径注入在 `BuildSystemPromptSections` | 实际在 `BuildSystemPromptWithMemory`(`context.go`) | 按旧函数名核对易误判"没做" | `internal/agent/context.go` |

前两项(1、2/3 的 todo 能力)是**功能欠账**,值得排期补;后三项(4、5、6)是**命名/路由漂移**,已在相关文档就地更正,不影响功能。全局技术债清单见 [STATUS.md §4](STATUS.md#4-已知欠账--技术债)。
