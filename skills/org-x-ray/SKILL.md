# Org X-Ray：组织研究文章撰写技能

## 投资分析的大前提

org-x-ray的终极目的不是写一篇好看的组织分析报告，而是**构建一个市场尚未充分认知的投资论点**。

核心命题：**"Founder not understood by market, but we believe him/her via org analysis."** 市场的典型模式是：founder在早期提出宏大愿景 → 市场不信（给予低估值或忽视）→ founder通过一系列艰难但一致的组织选择持续执行 → 业绩最终兑现愿景 → 市场疯涨。org-x-ray的价值在于：在"市场不信"和"业绩兑现"之间的窗口期，通过组织机制的深度拆解，建立conviction。

因此，文章的核心叙事不应该是"这个创始人做了哪些聪明的管理决策"（这是管理学研究），而应该是**"这个创始人有一个什么样的长期愿景，他为实现这个愿景做了哪些艰难的组织选择，这些选择的执行效果如何验证了愿景的可行性，以及市场目前是否已经price in了这些信息"**。

**叙事张力来自现实，不来自修辞。** 好的org-x-ray文章之所以有张力，不是因为用了漂亮的框架（"合规即护城河"、"算法即公司"），而是因为它揭示了一个真实的、市场尚未充分理解的差距——创始人已经在执行的组织现实 vs. 市场仍然给予的估值假设。

## 前置依赖：founder-decode

**org-x-ray不应直接启动。** 在动笔之前，必须先完成founder-decode流程，获得以下输入：
- 创始人长期愿景 + 坚固度评判
- 用户确认的🎯愿景驱动核心判断（作为文章主线）
- ⚡环境触发但愿景一致的判断（作为逆境验证素材）
- 🔄条件反射类判断（作为背景信息，不纳入核心叙事）
- 核心张力（市场不信 vs. 组织证据）
- 竞对差异化对比
- 真实动因评估（写作时的叙事偏差护栏）

如果用户要求跳过founder-decode直接写，应提醒这样做的风险（容易陷入"假设先行"的模式），但尊重用户决定。

## 核心定位

这是一个用于将第一手访谈材料、公开发言、书籍、内部文件转化为高质量**组织研究文章**的写作技能。

文章定位：介于学术研究和投资研究之间，面向关注公司长期竞争力的专业读者——基金经理、战略顾问、创始人。不是新闻报道，不是企业宣传，而是**愿景验证 + 机制拆解 + 逻辑验证 + 投资观点输出**。

参考系：本skill的写作标准对标"成事系列"激励研究文档——数据锚定、机制清晰、引语作论据而非叙事主体、用"战役级成果"验证组织设计的有效性。最终目标是让读者读完后能形成一个清晰的判断：**这个创始人的愿景是否值得相信，组织层面是否有足够的执行证据支撑这个信念。**

## 写作流程

### Step 1：材料收集与锚点识别

在写作前，必须先通过 `project_knowledge_search` 工具系统搜集材料，关键搜索词包括：
- 创始人/高管姓名 + 核心判断（如"Adam 量化基金 算法"）
- 组织机制名称（如"Pod结构"、"Revenue Impact"、"Chaos Monkey"）
- 数字和案例（如"人效 Meta 对比"、"IDFA危机 重组"）
- 关键转折节点（如"Axon 2.0 换血"、"剥离游戏业务"）

每篇文章需在写作前识别出以下**4个核心锚点**：

1. **创始人认知起点**：他看组织问题的独特视角从何而来（职业背景、关键经历）
2. **业务问题**：这家公司在其所在业务场景中，面临的最核心的组织-业务挑战是什么
3. **组织设计选择**：针对这个挑战，他做了哪些具体的机制设计，为什么这样而不是那样
4. **组织PMF验证**：哪些具体的"战役"或业务结果，证明这套组织设计在这个业务场景下是有效的

---

### Step 2：文章结构

文章结构**不是固定模板**，而是根据具体公司的材料动态确定。但所有文章都必须遵循以下**不可变的逻辑主线**：

```
封面页
  公司名（大字）
  副标题（点明核心洞察，格式："[核心动词]：[一句话框架]"）
  系列标签 + 日期 + 来源说明

Summary（必须包含）
  1段导语（3-4句，说清楚本文要回答的核心问题）
  编号Summary框（4条，每条格式：[标签]：[结论句]）

第一章：起点——创始人如何看组织（必须是第一章）
  核心判断的来源：背景经历如何塑造了他看组织的方式
  他对组织问题的独特定义：和主流管理思想的差异在哪
  这个判断的推论：他拒绝什么比他接受什么更有信息量

第二章至第N章：具体的组织设计（章节数量和标题根据材料灵活确定）
  ——必须承接第一章的认知框架展开，不能是孤立的机制列表
  ——覆盖范围按材料丰富程度取舍，可包括：核心机制设计、
    关键工具/系统的设计逻辑与演化、人才标准与激励机制、
    重大换血/重组节点及其背后的判断
  ——每章聚焦一个有足够深度可展开的组织主题
  ——每个核心机制遵循"四层结构"（见Step 3）

最后正文章节：组织设计与业务场景的适配性（必须存在）
  ——这家公司的业务场景有哪些特殊要求（速度/精度/创意/规模/可验证性等）
  ——这套组织设计为什么对这个业务场景有效，换一种组织形态会怎样
  ——用具体的战役/业务结果验证"组织PMF"

结语
  不超过3段
  必须包含：与同类公司做一句对比，点明这家公司的选择是什么

数据来源声明
```

**章节设计的判断原则**：
- 如果某个机制/工具足够复杂且材料丰富，单独成章
- 如果多个机制共享同一设计逻辑，合并成一章按层级展开
- 不要为了凑章节数而拆散应该放在一起的内容
- 章节标题直接点明核心机制或判断，不用抽象标题如"组织文化""管理哲学"

### Step 3：信息权重判断（写作前必须完成的取舍）

**在动笔之前，必须先显式完成一次机制分级**，以清单的形式列出所有已知机制，然后判断每条属于A类还是B类：

```
示例分级清单（AppLovin）：
- Pod独立竞争机制        → A类（核心）
- IDFA危机换血过程        → A类（核心）
- 商业敏感度招聘要求      → B类（注脚）
- GPU资源限制            → B类（注脚）
- 法律团队招聘标准        → B类（注脚）
- 低自尊管理文化          → B类（注脚）
```

**A类（核心机制）** 的判断标准——满足以下全部三条才算A类：
1. **必要性**：去掉这个机制，这家公司的核心竞争力会显著不同吗？
2. **可展开性**：这个机制的设计逻辑、执行难点、对人的要求，有足够丰富的一手材料支撑吗？
3. **因果链条**：这个机制和创始人在第一章的核心认知，有直接的逻辑因果关系吗？

**B类（支撑/次要机制）**：满足"有趣"但不满足以上三条全部的机制。

**写作规则：**
- A类机制：用四层结构完整展开（问题→设计逻辑→数字锚定→效果验证），通常1-2页
- B类机制：**一句话带过，不单独成段，不用引语，不用callout**——最多作为A类机制段落末尾的延伸注脚
- A类与B类的篇幅比，通常应在 **8:1 以上**。如果某篇草稿里A类和B类的展开接近，说明权重分配出了问题，需要返工

**操作检验：** 写完初稿后，通读一遍，问自己：如果读者只读了50%，他能清楚知道"这家公司最重要的组织选择是什么"吗？如果不能，说明A类机制没有得到足够突出的处理。

**AppLovin的正确分级示例：**
- A类（核心叙事）：
  - **Pod独立竞争机制**：150名ML工程师如何在相互隔离的"气泡"里各自推进Axon进化，这个机制的难点是什么（协调vs竞争的张力），对人的要求是什么（既能独立建模又要有商业判断）
  - **IDFA危机换血**：如何在2年内完成从传统ML到深度神经网络的组织代际跳跃，换血的执行逻辑和窗口期判断
- B类（一句话带过）：GPU资源限制、商业敏感度要求、法律团队招聘标准、低自尊管理文化——这些是AppLovin文化氛围的组成部分，但不是竞争力的决定因素，放入A类机制的展开段落里一句话点到即可

**最常见的权重失衡错误：**
- 把"有趣的细节"（GPU限制、商业敏感度）当成"重要的机制"来展开——细节丰富不代表重要性高
- 对所有机制分配相似的篇幅，导致读者无法判断哪个才是真正的核心
- 用B类机制的引语来填充章节，A类机制反而没有足够深的展开

### Step 3b：机制四层结构（A类核心机制的写作标准）

每个A类组织机制必须按以下四层展开，缺一不可：

**第一层：解决的问题**
明确说这个机制针对的是什么具体的业务或组织痛点。不是"提高效率"这类泛泛说法，而是"在IDFA政策切断用户归因链路后，旧模型的训练数据全面过时，广告ROI预测失效"这种可被精确识别的具体问题。

**第二层：设计逻辑——必须深入内部运作**
这是最容易写浅的一层。不能只描述"这个机制是什么"，必须进入机制内部，回答三个问题：

- **它如何运转**：日常的具体运作方式是什么，不是概念，而是操作层面的事实（谁做什么，按什么节奏，通过什么界面）
- **它的内部张力是什么**：这个机制在推进时面临的真实难点或矛盾（例：Pod隔离保证了竞争独立性，但也意味着工程师发现的好方法无法在团队间传播——这个张力如何管理？）
- **它对人的具体要求**：不是"聪明、有商业敏感度"这类泛化描述，而是这个机制要求一个人具体能做什么——比如"能在没有PM的情况下独立判断哪个实验方向值得跑，并在8周内交付完整的面向客户功能"

创始人/高管的原话引语放在这一层（见引语规范）。引语前必须有铺垫，引语后必须有组织含义点评。

**⚠️ 写完第二层后自查**：如果一个对这家公司一无所知的读者，读完这一层后仍然不清楚"在这家公司里做这个岗位是什么感受、难在哪里"，说明写得还不够深。

**第三层：数字锚定**
量化组织设计本身的参数和效果，必须是**直接指向业务结果或组织效率**的数字：
- 人效类：人均创收$400万（是Meta的近3倍）、150名ML工程师支撑数十亿美元营收
- 规模类：全公司800人、核心团队5人从零构建AXON
- 速度类：新任Director入职8周内交付完整面向客户的功能
- 对比类：AppLovin人均创收是Google的2倍、Meta近3倍、The Trade Desk的6倍以上

**⚠️ 禁止使用股价作为机制验证依据**：股价是市场情绪和多重因素的综合结果，不能作为组织设计有效性的直接论据。如需引用股价，只能作为背景信息，不能放入callout框作为验证。

**第四层：效果验证（战役级）**
用具体的"战役"验证机制有效性，优先级排序：

**①【最优】具体竞争战役**：某项组织设计帮助打赢了某个市场竞争。
例：拼多多赛马机制在买菜冷启动时打赢美团；AppLovin通过2年快速换血完成Axon 2.0，在IDFA危机后实现广告ROI预测反超Meta。

**②【次优】可归因的业务里程碑**：某时间节点前后的业务数据对比，能合理归因到组织机制。
例：Axon 2.0上线后，AppLovin软件业务收入从2022年$11亿增长到2024年$36亿，年复合增长率81%。

**③【兜底】可观察的行为/文化结果**：组织内部发生了什么可观察的行为变化。
例：Cursor在Shopify使用增长最快的群体是财务和销售，而非工程师，证明AI原生文化已穿透非技术部门。

用琥珀色callout框单独标注效果验证内容。

### Step 4：文风规范

#### 引语使用原则
- 引语是**论证支撑**，不是叙事主体——先提出论点，再用引语佐证
- 每段引语前必须有铺垫句（"这个逻辑的具体体现是……"/"他对这个问题的判断是……"）
- 引语后必须有点评句——明确说清楚这段话的**组织含义**
- 引语格式：用引语块（青色左边框+浅绿背景）呈现，来源注明"姓名, 职位, 时间"

#### 行文节奏
- 每个论点**先结论，后论据**——开门见山，直接说
- 段落长度：一个分论点通常3-4段展开，不要单段超过150字
- **禁止使用**：「可以看出」「由此可见」「不难发现」「值得注意的是」
- 章节标题直接点明机制本质（"算法取代销售团队"而非"商业模式创新"）

#### 数字使用原则
- 能用数字的地方不用形容词（不说"显著高于竞争对手"，说"是Meta的近3倍"）
- 对比数字优于孤立数字（"人均创收$400万，是The Trade Desk的6倍以上"）
- 时间序列数字揭示趋势（"软件收入从2022年$11亿增长到2024年$36亿，CAGR 81%"）

#### 结构标记词
- 递进：「更重要的是」「更深层的含义是」「这引出了第二个问题」
- 转折：「但问题在于」「这引出了一个反直觉的结论」「表面上看……实质上……」
- 结论：「这意味着」「对应到组织上」「落地的方式是」

### Step 6：质量自检清单

**内容层面**
- [ ] 写作前已完成A/B类机制分级，A类不超过3个
- [ ] B类机制一句话带过，没有单独成段或配引语
- [ ] 第一章聚焦创始人认知起点，而非公司简介或发展历史
- [ ] 第二至N章的组织设计，明确承接第一章的认知框架
- [ ] 每个核心机制有四层：问题→设计逻辑（含引语）→数字锚定→效果验证
- [ ] 至少1个「战役级」效果验证（竞争胜负或可归因业务里程碑）
- [ ] 最后正文章节专门论述「为什么这套组织设计对这个业务场景有效」
- [ ] 引语都有前置铺垫和后置点评，无裸引语
- [ ] 结语有与同类公司的对比句

**数字使用层面**
- [ ] 数字锚定直接指向业务结果或组织效率，无股价类数字作为验证依据
- [ ] 对比数字优先（X是Y的N倍），非孤立绝对值
- [ ] 无「大幅」「显著」「明显」等模糊形容词替代数字

**文风层面**
- [ ] 无「可以看出」「由此可见」「不难发现」
- [ ] 每个论点先结论后论据
- [ ] 章节标题直接点明机制本质

**文件层面**
- [ ] 字数5000字以上
- [ ] validate通过，段落数量合理（通常150+）

## 参考范文特征

**AppLovin《算法即公司》**
- 框架：量化交易员思维塑造广告算法公司的组织形态
- 关键数字：人均创收$400万（Meta近3倍、Google 2倍）、150名ML工程师、AXON初版5人构建

- 关键数字：Chaos Monkey清零>2人例会+2周禁建期、单季1000名实习生

**Anthropic《以智力换取智力》**

- 关键数字：超过70%的PR由Claude Code生成
